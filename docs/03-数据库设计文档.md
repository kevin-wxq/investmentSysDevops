# 投资系统运维闭环管理平台 — 数据库设计文档

> 版本：v3.0 | 分支：codex/devops-p1-linkage-hardening | 更新日期：2026-05-30
> 
> 数据库：MySQL 8.x | 字符集：utf8mb4 | 引擎：InnoDB

---

## 一、表总览

共 16 张业务表，分为 4 层：

| 层级 | 表名 | 说明 |
|------|------|------|
| **基础数据层** | ops_system_asset | 系统资产台账 |
| | ops_team_member | 运维团队成员 |
| | ops_vendor_contact | 供应商/联系人 |
| **日常运维层** | ops_duty_shift | 值班排班 |
| | ops_shift_log | 值班日志/交接班 |
| | daily_inspection_main | 巡检记录 |
| | ops_fault_record | 故障记录 |
| | ops_backup_record | 备份记录 |
| **核心闭环层** | ops_issue | 运维问题（入口） |
| | ht_bug_record | Bug记录 |
| | ht_requirement | 衡泰需求 |
| | ops_change_record | 变更记录 |
| | ops_work_item | 统一闭环事项 |
| | ops_work_item_log | 事项流转日志 |
| | ops_item_relation | 事项关系 |
| **知识沉淀层** | ops_knowledge | 运维知识库 |

## 二、核心闭环层（详细设计）

### 2.1 ops_issue — 运维问题

> 入口表，一切闭环从这里开始。问题分析后可转 Bug / 需求 / 变更。

| 字段 | 类型 | 可空 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | bigint(20) | NO | AUTO | 主键 |
| issue_no | varchar(64) | NO | | 问题编号 `OPS-ISSUE-YYYYMMDD-XXX`，UNIQUE |
| issue_type | varchar(32) | YES | OTHER | 问题类型(FUNCTION/CONFIG/DATA/PERFORMANCE/SECURITY/OTHER) |
| system_id | bigint(20) | YES | | 关联系统ID → ops_system_asset.id |
| system_name | varchar(100) | YES | | 系统名称（冗余） |
| module_code | varchar(32) | YES | | 所属模块(TRADE/VALUATION/CLEARING/COUNTERPARTY/REPORT/OTHER) |
| issue_title | varchar(200) | NO | | 问题标题 |
| issue_desc | text | YES | | 问题描述 |
| source_type | varchar(32) | YES | | 发现来源 |
| impact_scope | varchar(500) | YES | | 影响范围 |
| priority | varchar(16) | YES | P2 | 优先级(P0/P1/P2/P3) |
| founder | varchar(50) | YES | | 发现人 |
| found_time | datetime | YES | | 发现时间 |
| owner_id | bigint(20) | YES | | 负责人ID → ops_team_member.id |
| owner_name | varchar(50) | YES | | 负责人（冗余） |
| status | varchar(32) | YES | PENDING | 状态(PENDING/HANDLING/CLOSED/CONVERTED_BUG/CONVERTED_REQ/REJECTED) |
| handle_method | varchar(32) | YES | | 处理方式(CONFIG_FIX/DB_FIX/TO_BUG/TO_REQ/TO_CHANGE/OBSERVE/OTHER) |
| handle_result | text | YES | | 处理结果 |
| root_cause | varchar(32) | YES | | 根因分类(CODE_DEFECT/CONFIG_ERROR/ENV_ISSUE/DATA_ERROR/OTHER) |
| work_item_id | bigint(20) | YES | | 关联统一事项ID → ops_work_item.id |
| related_bug_no | varchar(64) | YES | | 转Bug后回写编号 |
| related_req_no | varchar(64) | YES | | 转需求后回写编号 |
| related_change_no | varchar(64) | YES | | 转变更后回写编号 |
| del_flag | char(1) | YES | 0 | 删除标记 |
| create_by | varchar(64) | YES | | 创建者 |
| create_time | datetime | YES | | 创建时间 |
| update_by | varchar(64) | YES | | 更新者 |
| update_time | datetime | YES | | 更新时间 |
| remark | varchar(500) | YES | | 备注 |

**索引：** uk_issue_no, idx_issue_type, idx_status, idx_priority, idx_system_id, idx_work_item_id

## 三、日常运维层（简要）

### 3.1 ops_duty_shift — 值班排班

关键字段：duty_date, shift_type(白班/夜班/全天), duty_member_id, backup_member_id, leader_id, shift_status

### 3.2 ops_shift_log — 值班日志

关键字段：shift_id, log_type(日常/事件/告警/交接), log_content, severity, handler_id, handover_from_id, handover_to_id

### 3.3 daily_inspection_main — 巡检记录

关键字段：inspection_date, inspector_id, system_name, cpu_usage, memory_usage, disk_usage, inspection_result(0异常 1正常), alarm_info

### 3.4 ops_fault_record — 故障记录

关键字段：system_id, fault_level(1一般 2严重 3紧急), fault_title, occur_time, recover_time, downtime_minutes, fault_status, knowledge_id(关联知识库)

### 3.5 ops_backup_record — 备份记录

关键字段：system_id, backup_type(1数据库 2文件 3配置 4全量), backup_result(1成功 2失败), restore_tested(0未验证 1已验证)

## 六、ER 关系图

```
ops_system_asset (系统资产)
    │ 1
    │
    ├──N ops_vendor_contact (供应商)
    ├──N ops_issue (运维问题)
    ├──N ht_bug_record (Bug)
    ├──N ht_requirement (需求)
    ├──N ops_change_record (变更)
    ├──N ops_work_item (统一事项)
    ├──N ops_fault_record (故障)
    ├──N ops_backup_record (备份)
    ├──N daily_inspection_main (巡检)
    └──N ops_knowledge (知识库)

ops_team_member (团队成员)
    │ 1
    │
    ├──N ops_duty_shift (值班) — duty_member_id
    ├──N ops_issue (问题) — owner_id
    ├──N ht_bug_record (Bug) — owner_id
    ├──N ops_change_record (变更) — executor_id / approver_id
    └──N ops_fault_record (故障) — handler_id

ops_issue (运维问题) ──GENERATE──→ ht_bug_record (Bug)
ops_issue (运维问题) ──CONVERT_TO─→ ht_requirement (需求)
ops_issue (运维问题) ──RELATE_TO──→ ops_change_record (变更)

ops_work_item ←──(自动同步)── ops_issue / ht_bug / ht_requirement / ops_change
ops_work_item_log ←──(状态变更时自动写入)── ops_work_item

ops_item_relation ←──(转化/关联时写入)── ops_issue → bug/req/change
```
