## 二、核心业务流转（闭环链路）

### 2.1 总览：问题驱动的闭环模型

```
                        ┌──────────┐
                        │  运维问题  │  ← 一切的起点
                        │ (ops_issue)│
                        └────┬─────┘
                             │ 分析判断
               ┌─────────────┼─────────────┬──────────────┐
               ▼             ▼             ▼              ▼
         ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
         │ 转 Bug   │  │ 转 需求  │  │ 转 变更  │  │ 直接处理 │
         │(ht_bug)  │  │(ht_req)  │  │(ops_chg) │  │ 关闭     │
         └────┬─────┘  └────┬─────┘  └────┬─────┘  └──────────┘
              │             │             │
              ▼             ▼             ▼
         ┌──────────────────────────────────────┐
         │       ops_item_relation (关系表)       │
         │  记录 Issue↔Bug/Req/Change 的关联链路  │
         └──────────────────┬───────────────────┘
                            │
                            ▼
         ┌──────────────────────────────────────┐
         │       ops_work_item (统一事项)         │
         │  所有模块创建/更新时自动同步到此表      │
         │  → ops_work_item_log (状态流转日志)    │
         └──────────────────┬───────────────────┘
                            │
                            ▼
                      ┌──────────┐
                      │ 报告中心  │  ← 数据汇总与导出
                      └──────────┘
```

### 2.2 运维问题状态流转

```
PENDING (待处理)
    │
    ├──→ HANDLING (处理中) ──→ CLOSED (已关闭)
    │
    ├──→ CONVERTED_BUG  (已转Bug)    ← 调用 convertToBug()
    │
    ├──→ CONVERTED_REQ  (已转需求)   ← 调用 convertToRequirement()
    │
    └──→ REJECTED (已驳回)
```

**关键操作：**
- **转Bug**：创建 HtBugRecord → 设置 issue.status = CONVERTED_BUG → 写入 ops_item_relation (GENERATE) → 同步 WorkItem
- **转需求**：创建 HtRequirement → 设置 issue.status = CONVERTED_REQ → 写入 ops_item_relation (CONVERT_TO) → 同步 WorkItem
- **幂等保护**：已转Bug/需求的 Issue 不可重复转换，直接返回已有记录

### 2.3 Bug 状态流转

```
WAIT_CONFIRM (待确认)
    │
    ├──→ CONFIRMED (已确认)
    │       │
    │       ▼
    │   FIXING (修复中)
    │       │
    │       ▼
    │   FIX_COMPLETE (修复完成)
    │       │
    │       ▼
    │   WAIT_RETEST (待验证)
    │       │
    │       ├──→ VERIFIED (验证通过) ──→ PUBLISHED (已发布) ──→ CLOSED (已关闭)
    │       │
    │       └──→ REOPEN (退回修复) ──→ FIXING
    │
    └──→ REJECTED (已驳回)
```

**新增闭环字段（P1）：**
- `verifier_id / verifier_name / verify_time / verify_result / verify_detail` — 验证人/时间/结果/说明
- `patch_no` — 补丁号，串联发布
- `fix_complete_time` — 修复完成时间
- `online_time` — 实际上线时间

### 2.4 需求状态流转

```
WAIT_ANALYSIS (待分析)
    │
    ├──→ ANALYZING (分析中)
    │       │
    │       ▼
    │   WAIT_CONFIRM (待确认)
    │       │
    │       ├──→ IN_BUSINESS (商务流程中)
    │       │       │
    │       │       ▼
    │       │   WAIT_SCHEDULE (待排期)
    │       │
    │       └──→ WAIT_SCHEDULE (待排期)
    │               │
    │               ▼
    │           DEVELOPING (开发中)
    │               │
    │               ▼
    │           WAIT_ACCEPT (待验收)
    │               │
    │               ├──→ ONLINE (已上线)
    │               │
    │               └──→ REJECTED (退回)
    │
    └──→ REJECTED (已驳回)
```

**新增闭环字段（P1）：**
- `patch_no` — 补丁号
- `analysis_detail` — 分析详情
- `acceptance_detail` — 验收详情

### 2.5 变更状态流转

```
APPLYING (申请中)
    │
    ├──→ WAIT_APPROVE (待审批)
    │       │
    │       ├──→ APPROVED (已审批)
    │       │       │
    │       │       ▼
    │       │   EXECUTING (执行中)
    │       │       │
    │       │       ▼
    │       │   WAIT_VERIFY (待验证)
    │       │       │
    │       │       ▼
    │       │   ARCHIVED (已归档)
    │       │
    │       └──→ REJECTED (已驳回)
    │
    └──→ REJECTED (已驳回)
```

**P1 增强：**
- 自动生成变更编号 `CHG-YYYYMMDD-XXX`
- 创建时自动建 WorkItem，状态同步
- 验证闭环：`verify_result / verify_detail / patch_no`

## 三、数据流转图

### 3.1 写入流转（创建/更新）

```
用户操作前端
    │
    ▼
Controller 接收请求
    │
    ▼
Service 层处理
    │
    ├──→ 写入源表（ops_issue / ht_bug_record / ht_requirement / ops_change_record）
    │
    ├──→ 调用 opsWorkItemService.createFromSource() 或 syncFromSource()
    │       │
    │       ├──→ 写入/更新 ops_work_item
    │       │
    │       └──→ 写入 ops_work_item_log（状态变更时）
    │
    └──→ 转化操作时，写入 ops_item_relation
```

### 3.2 WorkItem 同步机制

| 来源模块 | sourceModule | 触发时机 | 映射规则 |
|----------|-------------|----------|----------|
| 运维问题 | `OPS_ISSUE` | insert / update | PENDING→PENDING, 其他→PROCESSING, CLOSED→CLOSED |
| Bug | `HT_BUG` | insert / update | WAIT_CONFIRM→PENDING, WAIT_RETEST→ACCEPTING, CLOSED→CLOSED |
| 需求 | `HT_REQUIREMENT` | insert / update | WAIT_ANALYSIS→PENDING, WAIT_ACCEPT→ACCEPTING, ONLINE→CLOSED |
| 变更 | `OPS_CHANGE` | insert / update | APPLYING→PENDING, ARCHIVED→CLOSED, EXECUTING→PROCESSING |

### 3.3 WorkItem 状态回写源表（T4）

```
ops_work_item 状态变更
    │
    ▼
writeBackToSource(item)
    │
    ├──→ sourceModule = "OPS_CHANGE" → 更新 ops_change_record.status
    │
    └──→ 其他模块由各自的 Service.update() 自行同步（避免循环）
```

### 3.4 事项关系记录

```
ops_item_relation
┌──────────────────────────────────────────────────────────┐
│ source_type │ source_no │ target_type │ target_no │ type │
├─────────────┼───────────┼─────────────┼───────────┼──────┤
│ OPS_ISSUE   │ OPS-ISSUE │ HT_BUG      │ BUG-xxx   │GENERATE
│             │  -xxx     │             │           │      │
│ OPS_ISSUE   │ OPS-ISSUE │ HT_REQUIREMENT│ FI-REQ  │CONVERT_TO
│             │  -xxx     │             │  -xxx     │      │
└──────────────────────────────────────────────────────────┘
```

## 四、日常运维流转

### 4.1 值班 → 巡检 → 问题发现

```
ops_duty_shift (值班排班)
    │
    ├──→ ops_shift_log (值班日志 / 交接班)
    │
    └──→ daily_inspection_main (巡检记录)
            │
            ├──→ 巡检正常 → 记录归档
            │
            └──→ 巡检异常 → 发现问题
                    │
                    ▼
              ops_issue (运维问题) → 进入核心闭环
```

### 4.2 故障处理

```
ops_fault_record (故障记录)
    │
    ├──→ 直接处理 → 记录根因/方案 → 关闭
    │
    └──→ 关联知识库 → ops_knowledge
```
