# 投资系统运维与需求闭环管理平台整体规划

## 1. 系统定位

本系统定位为“投资系统运维与需求闭环管理平台”，面向信息技术部、业务部门、厂商和验收人员，统一承载系统资产、运维事件、需求、Bug、变更、报告和知识沉淀。

系统建设目标不是单纯做表单登记，而是形成可跟踪、可验收、可归档、可汇报的闭环管理平台。

## 2. 建设目标

- 统一管理投资相关系统的资产、人员、供应商和字典基础数据。
- 对需求、Bug、故障、巡检异常、备份异常、变更事项建立闭环机制。
- 对衡泰需求建立从提报、编号、评审、分析、商务、排期、开发、验收到上线归档的全流程管理。
- 支持按周、月、部门、系统、事项类型生成完整报告。
- 支持管理层通过看板掌握系统健康、需求交付、风险事项和逾期情况。

## 3. 总体业务域

### 3.1 基础资源域

基础资源域提供系统运行所需主数据。

- 系统资产台账
- 运维团队成员
- 供应商联系人
- 部门、模块、优先级、状态等字典
- 菜单、角色、权限

### 3.2 日常运维域

日常运维域记录常规运维动作。

- 值班排班
- 值班日志
- 日常巡检
- 健康状态
- 告警处理

巡检异常、告警异常应能转入统一事项闭环。

### 3.3 事件与风险域

事件与风险域管理影响系统稳定性的事项。

- 故障登记
- 影响范围
- 处理过程
- 恢复时间
- 根因分析
- 预防措施
- 复盘结论

故障闭环后应沉淀为知识库材料。

### 3.4 变更发布域

变更发布域管理生产调整和上线风险。

- 变更申请
- 风险等级
- 执行计划
- 回退方案
- 审批人
- 执行结果
- 验证结果
- 发布归档

### 3.5 需求与 Bug 域

需求与 Bug 域是下一阶段重点建设内容。

- 衡泰需求登记
- 需求跟踪
- 周会评审
- 厂商分析
- 商务排期
- 开发跟进
- 测试验收
- 上线归档
- Bug 登记
- Bug 分派
- 修复回归
- 关闭确认

需求和 Bug 均需支持编号、状态流转、附件、处理日志和报告导出。

### 3.6 报告与驾驶舱域

报告与驾驶舱域面向汇报和归档。

- 运维周报
- 运维月报
- 衡泰需求交付报告
- Bug 处理报告
- 故障复盘报告
- 变更发布报告
- 系统健康报告
- 综合管理报告

报告优先支持 Excel 明细导出，再扩展 Word/PDF 汇报版。

## 4. 统一闭环模型

需求、Bug、故障、巡检异常、备份异常、变更异常统一抽象为“事项”。

统一事项字段建议：

- 事项编号
- 事项类型
- 来源模块
- 关联系统
- 优先级
- 当前状态
- 责任人
- 提出人
- 提出时间
- 计划完成时间
- 实际完成时间
- 处理进展
- 验收结果
- 关闭说明
- 附件
- 备注

闭环判定标准：

- 有唯一编号
- 有责任人
- 有处理过程
- 有验收结果
- 有关闭时间
- 有状态流转日志

## 5. 衡泰需求管理规划

需求编号规则：

`部门编码-REQ-YYYYMMDD-XXX`

示例：

`FI-REQ-20260530-001`

部门编码、需求优先级、所属模块、当前状态、是否涉及商务、分析结果、验收人、验收结果均使用字典项。

状态流转：

`待分析 -> 分析中 -> 待确认 -> 商务流程中 -> 待排期 -> 开发中 -> 待验收 -> 已上线`

特殊流转：

- `待分析 / 分析中 / 待确认 -> 已驳回`
- `待验收 -> 开发中`

核心页面：

- 需求看板
- 需求登记
- 需求跟踪
- 周会评审
- 厂商分析
- 商务排期
- 测试验收
- 需求归档

## 6. Bug 管理规划

Bug 编号规则建议：

`BUG-YYYYMMDD-XXX`

核心字段：

- Bug 编号
- 关联需求编号
- 关联系统
- Bug 标题
- 严重级别
- 优先级
- 复现步骤
- 预期结果
- 实际结果
- 指派人
- 修复人
- 修复说明
- 回归测试人
- 回归结果
- 当前状态

状态流转：

`待确认 -> 待修复 -> 修复中 -> 待回归 -> 已关闭`

特殊流转：

- `待确认 -> 已驳回`
- `待回归 -> 修复中`

## 7. 报告中心规划

报告中心应支持筛选周期、部门、系统、事项类型后导出。

### 7.1 综合报告内容

- 本期新增事项数量
- 本期闭环事项数量
- 未闭环事项数量
- 逾期事项数量
- P0/P1 重点事项
- 各部门需求分布
- 各系统问题分布
- 本期上线清单
- 故障恢复时长
- 变更成功率
- 备份成功率
- 风险与待协调事项
- 明细台账

### 7.2 导出形式

- Excel：明细台账、统计清单
- Word：正式汇报材料
- PDF：归档版报告

## 8. 菜单规划

建议最终一级菜单：

- 工作台
- 基础资源
- 值班巡检
- 故障变更
- 需求管理
- Bug 管理
- 报告中心
- 知识库
- 系统管理

原“系统运维管理 / 日常运维明细”旧模块已不纳入后续规划，当前应下线清理。

## 9. 分阶段任务规划

### 阶段一：模块清理与规划固化

- 下线旧“系统运维管理 / 日常运维明细”模块。
- 保留可复用基础资源能力。
- 固化整体规划文档。
- 清理无效菜单和旧入口。

### 阶段二：统一闭环基础能力

- 新增统一事项主表。
- 新增事项状态流转日志。
- 新增附件管理。
- 新增逾期识别字段和查询条件。
- 统一编号生成能力。

### 阶段三：衡泰需求管理

- 新增需求登记和跟踪表。
- 配置衡泰需求相关字典。
- 实现需求编号自动生成。
- 实现需求状态流转。
- 实现周会评审、厂商分析、商务排期、验收归档。

### 阶段四：Bug 管理

- 新增 Bug 主表。
- 支持 Bug 关联需求。
- 实现修复、回归、关闭流程。
- 形成 Bug 闭环统计。

### 阶段五：报告中心

- 先实现 Excel 明细报告。
- 再实现 Word/PDF 汇报版。
- 支持按周、月、部门、系统生成综合报告。

### 阶段六：驾驶舱升级

- 展示未闭环、逾期、P0/P1、待验收、已上线等关键指标。
- 展示系统维度、部门维度、厂商维度统计。
- 支持从图表钻取到明细。

## 10. 设计原则

- 编号由系统生成，禁止手工维护。
- ID 字段不直接暴露给业务用户。
- 状态通过流程按钮流转，不做自由文本。
- 字典统一维护。
- 事项必须闭环。
- 报告必须可导出、可归档。
- 已闭环数据保留历史，不物理删除。
- 操作过程保留日志，便于追溯。
