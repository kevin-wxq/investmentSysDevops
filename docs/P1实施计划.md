# P1 实施计划：闭环联动与验证增强

分支：codex/devops-p1-linkage-hardening

---

## 任务拆解

### T1：变更记录接入 WorkItem + Relation
- 变更记录 Service 调用 `createFromSource` / `syncFromSource`
- 变更记录创建时生成 WorkItem
- 变更状态同步到 WorkItem
- 后端：`OpsChangeRecordServiceImpl.java`
- 前端：`changeRecord/index.vue` 增加关联事项和状态联动

### T2：Bug/需求创建时同步写 Relation
- `HtBugRecordServiceImpl` 创建时写 `OPS_ISSUE → HT_BUG` 关系
- `HtRequirementServiceImpl` 创建时写 `OPS_ISSUE → HT_REQUIREMENT` 关系
- 前端 Bug/需求详情增加关联链路表格

### T3：转 Bug/转需求加幂等保护
- `OpsIssueServiceImpl.convertToBug()` 前检查 status != CONVERTED_BUG
- `OpsIssueServiceImpl.convertToRequirement()` 前检查 status != CONVERTED_REQ
- 已转则直接返回，不重复创建

### T4：WorkItem 状态回写源表
- `OpsWorkItemServiceImpl.updateOpsWorkItem()` 增加回写逻辑
- 根据 `sourceModule` + `sourceId` 反查源表并同步 status

### T5：Bug 验证闭环
- `HtBugRecord` domain 增加字段：verifier_id, verifier_name, verify_time, verify_result, verify_detail, patch_no, online_time, fix_complete_time
- SQL 增加对应字段
- 前端增加"验证通过/验证不通过/退回修复"按钮
- Bug 状态流转增强：待确认 → 修复中 → 修复完成 → 待验证 → 验证通过 → 已发布 → 已关闭

### T6：需求验收增强
- `HtRequirement` domain 增加字段：patch_no, analysis_detail, acceptance_detail
- SQL 增加对应字段
- 前端增加验收退回操作

### T7：变更验证闭环
- 变更增加 verify_result, verify_detail, patch_no, work_item_id
- 变更状态流转：申请中 → 待审批 → 已审批 → 执行中 → 待验证 → 已归档
- 变更执行完成自动创建 Relation（CHANGED_BY）

### T8：前端权限补齐
- 所有按钮补 `v-hasPermi`
