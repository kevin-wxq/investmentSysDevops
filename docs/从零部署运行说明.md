# 从零部署运行说明

本文用于说明：如何从零拉取本项目分支、初始化数据库、启动后端与前端，并进入系统验证。

## 1. 拉取代码

```bash
git clone <你的仓库地址> investmentSysDevops
cd investmentSysDevops
git fetch origin
git checkout -b codex/devops-p0-stabilization origin/codex/devops-p0-stabilization
```

如果本地已经有仓库，只需要：

```bash
git fetch origin
git checkout codex/devops-p0-stabilization
git pull origin codex/devops-p0-stabilization
```

## 2. 环境要求

- JDK 8
- Maven 3.x
- Node.js 8+（建议 14/16）
- MySQL 5.7/8.0
- Redis

## 3. 数据库初始化顺序

数据库名默认使用 `devops`。

### 3.1 全量初始化

如果是全新数据库，按下面顺序执行：

```bash
mysql -uroot -p devops < sql/运维建表_v4.sql
mysql -uroot -p devops < sql/运维字典.sql
mysql -uroot -p devops < sql/运维菜单.sql
mysql -uroot -p devops < sql/运维问题与事项关系模块.sql
```

### 3.2 已有旧库增量升级

如果数据库里已经有旧表，只补本分支新增内容即可：

```bash
mysql -uroot -p devops < sql/运维字典.sql
mysql -uroot -p devops < sql/运维菜单.sql
mysql -uroot -p devops < sql/运维问题与事项关系模块.sql
```

### 3.3 本分支涉及的关键 SQL

- `sql/运维字典.sql`
  - 补充 `ops_issue_type`
  - 补充 `ops_issue_status`
  - 补充 `ops_handle_method`
  - 补充 `ops_root_cause`
  - 补充 `ops_relation_type`
  - 补充 `ops_item_type` 的 `ISSUE`
- `sql/运维菜单.sql`
  - 新增“运维问题”菜单
  - 新增“事项关系”权限
- `sql/运维问题与事项关系模块.sql`
  - 新增 `ops_issue`
  - 新增 `ops_item_relation`

## 4. 后端启动

在项目根目录执行：

```bash
mvn -DskipTests package
java -jar ruoyi-admin/target/ruoyi-admin.jar
```

默认后端地址：

```text
http://localhost:8080
```

## 5. 前端启动

进入前端目录：

```bash
cd ruoyi-ui
npm install
npm run dev
```

默认前端地址：

```text
http://localhost:8081
```

## 6. 登录账号

- 账号：`admin`
- 密码：`admin123`

## 7. 验证路径

登录后依次检查：

- 运维管理
- 闭环中心
- 运维问题

重点看：

- 新增弹窗是否分区清晰
- 问题编号是否自动生成
- 查询条件默认是否为空
- 转 Bug / 转需求是否可用
- 详情页关联链路是否正常显示

## 8. 本分支新增功能说明

本分支已补齐：

- 运维问题入口
- 事项关系链路
- 转 Bug
- 转需求
- 统一字典
- 菜单权限
- 需求说明与设计说明文档

## 9. 备注

如果你的 MySQL 密码不同，把命令里的 `-p` 后面改成自己的即可。
如果 Redis 或 MySQL 已经有旧进程，先确认端口未被占用再启动。
